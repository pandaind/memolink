# MemoLink Core - Developer Learnings

This document is a technical deep-dive into `memolink-core`, designed for mid-level Java developers to understand how the library works under the hood.

> [!NOTE]
> `memolink-core` is the engine that drives MemoLink. It is responsible for parsing Markdown files, generating AI embeddings, discovering relationships, and building an in-memory Knowledge Graph that can be searched and traversed.

## Tech Stack & Dependencies
The core module is built with **Java 21** and heavily utilizes **Spring Boot 3.x** and **Spring AI** concepts, though it can function primarily as a library. 

Key dependencies include:
- `com.vladsch.flexmark`: For robust Markdown parsing, including wiki-link extensions (`[[link]]`).
- `com.microsoft.onnxruntime`: For running local vector embedding generation directly in the JVM.
- `org.apache.lucene`: For building an inverted index to support fast text-based searching across notes.

## Architecture & Pipeline

The pipeline of processing a directory of Markdown files follows a distinct orchestration flow, primarily managed by the **[GraphBuilderService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/GraphBuilderService.java)**.

### 1. Scanning
**[MdFileScannerService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/MdFileScannerService.java)** walks the directory tree starting from the root of your vault to discover all `.md` files.

### 2. Parsing & Metadata Extraction
**[MdFileParserService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/MdFileParserService.java)** reads each file and uses `flexmark` to extract critical signals:
- **Wiki Links**: Matches `[[note]]` and normalizes the target to a standard ID (e.g., `note.md`). It also supports typed links like `[[note|relationship]]`.
- **Tags**: Extracts hashtags (e.g., `#java`).
- **Keywords**: Strips formatting and stop-words ("the", "and", etc.), then counts frequencies to determine the top 15 keywords for the file.
- **Frontmatter**: Extracts properties like `importance` from YAML frontmatter if present.

### 3. AI Embeddings (Vectorization)
**[EmbeddingService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/EmbeddingService.java)** vectorizes the text for semantic similarity.
- It calculates an embedding for the entire file.
- It chunks the file into paragraphs and calculates chunk-level embeddings.
- **Caching**: Generating embeddings is CPU-intensive. `GraphBuilderService` caches timestamps and embeddings into a `.memolink/` directory so subsequent runs or incremental rebuilds are significantly faster.

### 4. Relationship Engine
**[RelationshipEngine](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/RelationshipEngine.java)** is responsible for connecting the dots. It avoids a naive O(N²) comparison by using inverted indexes (tag → note IDs, keyword → note IDs). 

It builds weighted edges based on:
1. **Explicit Links (Wiki Links)**: Highly weighted (+5).
2. **Shared Tags**: Moderately weighted (+2 per tag, up to a max of 3 tags).
3. **Shared Keywords**: Lightly weighted (+1 per keyword, up to a max of 5).

Any pair of notes that score `> 0` form a bidirectional edge in the graph. The relationship type is automatically inferred (e.g., `references`, `related_topic`) or explicitly provided via wiki-link syntax (`[[target|type]]`).

### 5. In-Memory Graph
All this data is finalized into the **[KnowledgeGraph](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/model/KnowledgeGraph.java)**. This class contains:
- `List<GraphNode>`: The parsed markdown notes (`MdFileMetadata`).
- `List<GraphEdge>`: The relationships generated by the Relationship Engine.
- An internal adjacency list used for quick graph traversal (e.g., "give me all neighbors of Node X").

## Searching & Traversal

Once the `KnowledgeGraph` is built, we have additional services to interact with it:

- **[GraphSearchService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/GraphSearchService.java)**: When the graph is built, this service indexes the markdown content into a transient Apache Lucene directory. This allows for ultra-fast, fuzzy, and boolean text queries.
- **[GraphTraversalService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/GraphTraversalService.java)**: Performs Breadth-First Search (BFS) to find paths between nodes or gather a cluster of related nodes up to a certain depth.
- **[GraphWatchService](file:///Users/cpanda/Projects/memolink/memolink-core/src/main/java/ist/logic/core/service/GraphWatchService.java)**: Uses `java.nio.file.WatchService` to monitor the file system for updates, triggering an incremental rebuild in `GraphBuilderService` when a note is edited.

## Summary for Java Developers

If you are expanding this library:
1. **Model Changes**: Add new fields to `MdFileMetadata` if you want to extract more signals (e.g., tasks or external URLs).
2. **Parsing**: Update `MdFileParserService` and register a new `flexmark` visitor if you add new syntax (like custom callouts).
3. **Graph Weights**: Tweak weights in `RelationshipEngine` to tune how aggressively notes relate to each other.
4. **Performance**: Always respect the incremental build and caching mechanisms in `GraphBuilderService`; calculating embeddings for thousands of files on every startup will freeze the application.
